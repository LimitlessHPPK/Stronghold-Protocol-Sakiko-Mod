# 本地修改清单（相对上游 v0.2.1）

这份文档给**想对照上游**的人：本版改过哪些文件、新增了哪些文件、哪些是**生成物**（要重跑而不是手改）。
上游原版：<https://github.com/sganggs/Stronghold-Protocol>（`releases/tag/v0.2.1`）；原版说明保留在仓库根的
`README-上游原版.md`。

> 目录树对比结果：**新增 26 · 修改 63 · 删除 0**（其中若干条目只是行尾差异）。
>
> ⚠️ **升级到更新的上游版本时不要整目录覆盖**：上游会改动同样的文件，盲目覆盖会回退官方修正、
> 也会丢掉本版成果。正确做法是**按功能重放补丁**，并且**生成物一律重跑生成、不做文本合并**。

## 七、上游更新时的做法（本项目的经验）

1. **先读新版 CHANGELOG**，确认哪些是上游已按官方重做的（例如 v0.1.3→v0.1.4 的高台规则、缇缇沉睡计数）——**不要把这些覆盖回旧行为**；
2. 用**完整包**（源码归档）做基线，把本版功能**逐条重放**（`git am --3way` 或手工），**别整目录覆盖**；
3. **生成物重跑**（第六节），不要文本合并；
4. 跑 `node --test --test-concurrency=3`（`fullmatch*` 系列每个文件要 9–11 分钟，高并发会伪造帧耗时基准失败）
   与 `node tools/golden.mjs`，确认只有预期场景变化；
5. 渲染层（`public/js/render/**`）改动**必须跑一次真浏览器**（`RENDER_E2E=1` + `CHROME_PATH`）——
   这类问题能完全逃过单测（本项目踩过：一个标识符写错导致整页降级为简化视图，而纯函数测试全绿）。
6. 注意 **v0.2.1 起官方提供增量更新包**（按 `MANIFEST.json` 校验程序文件）——本仓库是改过的，
   **不能用增量包升级**，只能用完整包重放。
