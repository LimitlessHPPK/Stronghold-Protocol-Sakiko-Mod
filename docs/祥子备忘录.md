## 2. 为她实现的机制（玩法）

1. **音符＝普攻载体**：`trait: { noAttackVis, noAttackDamage }`——普攻**不画箭**、箭**不结算伤害**，
   伤害与攻击回复技力**都在音符命中时**结算；命中判定**不含伤害量**（护盾全吃/闪避/无敌也算击中）。
   两个字段是**引擎的显式 opt-in**，只有她设；同为领主、同用 `arrow` 的拉普兰德行为不变（回归证据）。
2. **持续攻击**：射程内无敌人也持续发射；唯一限制「**前方一格通行类型为无**」才停（**障碍物也挡**，
   「只走不飞」的地块不挡）；空转时音符命中敌人**照常补回**攻击回复技力（"击中就加"）。
3. **音符三态飞行**：官方【自由移动】→【追踪移动】→【已命中】（她的音符**没有**【已命中】，命中即消失）；
   参数逐技能取自 §17 的 PRTS 表（S1 自由 1.7/追踪 2.2、S2 钢琴 3.5+【已命中】0.8 碰撞、S2 风琴 1.0、
   S3 1.3、天赋有目标 2.0/无目标 扩张正弦 0.3+1.3 …）。
4. **Fever（天赋二 + 官方备注）**：计量 **0–450**，**蓄满后任意一次技能发动**触发 **20 秒**、**在场全员共享**；
   期间**不累积 / 停止回技力 / 压制常规自动发动 / 免技力无视技力限制持续释放**（切换类 S2 除外）；
   进入前在跑的持续类技能**暂停计时**，凭 Fever 开的持续类技能**结束时强制结束**；S3 免死（被救者退场）。
5. **三个技能**：S1 八音符扇形（法术 65%→4%，可充能 2 次，**充能至上限自动释放一次**）；
   S2 切换类（钢琴/风琴、Fever 期间二连击）；S3 范围扩大 + 物理/法术各 2 音符**分别追踪法抗/防御最高者**。
6. **模组 LOR-Y**：穿甲逐档 `3%/2%/10 层`（base 与 1 级）、`4%/2%/12`（2 级）、`5%/2.5%/12`（3 级）；
   **「技能期间远程攻击不再降低攻击力」**（2/3 级）；条件攻速 +12 由**引擎**的 `traitMods.js` 提供（kit 不再实现第二遍）。
7. **可见与可听**：`snap.proj` 出音符的权威位置 → 客户端画八分/十六分/高音谱号精灵；
   `snap.fever` 出计量 → 模型右下角玫红图标（蓄满光效、**无 50% 刻度**）+ Fever 期间 **SP 条染玫红**。

### 3.2 普攻"两段等额伤害"（所有者裁定方案 A）

- **现象**：一次普攻打出**两段等额伤害**（箭在 0.133 s 结算 + 天赋音符在 0.933 s 结算，各 469.6）。
- **依据**：PRTS「**所有音符强制使用缓存攻击力与攻击倍率**」，天赋自身没有任何伤害倍率字段 ⇒ **箭是重复计算**。
- **修法**：引擎按 profile 的 `noAttackDamage` 让箭不结算伤害、也不算"演完这次攻击"；伤害与攻回技力都在音符命中时结算。
- **代价**：她的**普攻伤害减半**（修掉重复计算后的正确值）。
- **回归证据**：同为领主、同用 `arrow` 的**拉普兰德仍是箭**、仍在 0.133 s 落地结算。

### 3.3 移植到 v0.2.1 时的数值/计数（满潜能）

- v0.2.1 起**干员按满潜能计算**（含精锐与自选）⇒ 她：atk `587→613`、`678→704`，cost `20→18`，
  部署 `70→66`，天赋二攻速 `+12→+16`；golden 只有含她的 `diy-135/136` 变化，其余 5 家族与 138 个自选场景**逐位不变**。

### 3.4 **LOR-Y「技能期间远程攻击不再降低攻击力」漏做**（所有者要求补，2/3 级都要对）

- **现象**：装了 LOR-Y 之后，**技能期间的音符仍然吃领主那 0.8 的远程倍率**，比官方少 20% 伤害。
- **根因**：这句**没有黑盒键**，只存在于模组 2/3 级的**天赋文本**里（`uniequip_002_oblvns` 的 phase 2/3 才多出 TALENT 部件），
  而音符的伤害倍率快照只看 `profile.dmgMul`、**完全不看模组与技能状态**。
- **修法**：按**解析记录里的那句话**判定（不是硬编码档位号）⇒ **2 级/3 级命中、base 与 1 级不命中**；
  「技能期间」取引擎的 `unit.skill.active`（+ 释放当 tick）；S1 瞬发的八只音符在 `onStart` 一次性取好窗口；
  Fever 的免费释放同路径。**只在她 kit 的 6 个音符发射点生效**，没有动共享的 `profile.dmgMul`。
- **注意**：**2 级在自选路径不可达**（槽位的 `equipLevel` 只有 1/3），所以 2 级是**按官方 phase 2 数据构造记录**测的。
- **提交**：`21bb3c6`。

### 3.5 普攻音 / 命中音**在 0.2.x 整个丢失**（0.1.4 → 0.2.x 的移植回归）

- **现象**：她攻击敌人时**没有挥击音、敌人受击没有命中音**。
- **根因（两段叠加）**：
  1. 0.1.4 里她是**普通棋子**，通用素材管线顺带解析出了 `attack`/`hit`；改成**自选干员**后，那两个 mp3 **从没被下载**；
  2. 清单生成器 `manifest.mjs` 对「**备选文件都不在磁盘上**」的叶子**静默丢弃** ⇒ 两个键从 `data/assets.json` 里消失（而不是留着报 404）。
  事件流一直是好的（实测 `['atk',她,敌,'none']` → 900 ms 后 `['dmg',敌,490,'arts']`，在客户端 2500 ms 归因窗口内）。
- **修法**：补齐两个文件（与官方 dump、与 0.1.4 的两份**同 sha256**）+ 加 **`UNIT_SFX_BANKS`** 钉住 0.1.4 的取值（防漂移）
  + 把 7 个技能音文件名**统一成小写**（原先清单小写、磁盘大写 `MJC`，**Windows 能用、Linux 部署会 404**）。
- **提交**：`a65ed0f`。

### 3.6 音符**诞生音从来没响过**（真浏览器取证）

- **现象**：发出音符时**没有任何声音**（技能音符也一样；当时听到的"技能音"其实是技能自身的施放音）。
- **根因**：`_noteFired` 的守卫调的是 **`api.play(...)`——而 `AudioManager` 根本没有 `play` 方法**
  （入口是 `playProj` / `unit` / `battle` / `sfx` / `voice`）⇒ **每一次"发出音符"都在守卫处静默 return**。
- **取证**：真浏览器（puppeteer + 本机 Edge + 自家 fast server + `/dev/grant` 发牌 + 真拖拽部署）：
  修前 `playProj calls (0)`、`_play` 里天赋诞生 **0** 次；修后天赋 **21 次**、技能 **16 次**。
- **修法**：改调 `playProj(kind, {unitId, unit})`（保留 `play` 兜底旧 harness）+ 清单加**通用**的投射物音效栏
  `audio.sfx.proj.{note,noteSkill}.born`；命中音仍走 `dmg` 归因（**音符"消失"不播命中音**——那可能是超时消失）。
- **测试教训**：原有 76 项音效测试没抓到，是因为 `fxnote.test.js` 的 `soundSink()` 是**只带 `play` 的假 sink**
  ——它测的是客户端并不存在的 API。现在新增 `projSink`（**真 API 面**）并钉住 `typeof AudioManager.prototype.play === 'undefined'`。
- **提交**：`d7b7716`（含探针 `test/e2e/sakiko-note-sfx-probe.mjs`，以及顺带修掉"探针参数被 puppeteer 静默丢弃"的真 bug）。

### 3.7 场上有两只她时**只响一只**

- **现象**：两只祥子同时开火，只有一只的音效被听到。
- **根因**：客户端 `SfxLimiter` 用**一个全局 `lastByUrl`** 做"同一 URL 的最小间隔"，而**一条 socket 消息里的两个单位共享同一个时间戳** ⇒ 第二只**必然**被第一只按掉。
- **修法**：最小间隔改为按 **(URL, 单位)**；不失控靠三道非每单位的闸：整场并发 `MAX_VOICES 8`、同一文件最多 `MAX_PER_URL 2`（官方 `maxSoundAllowed`）、每单位 160 ms 冷却 —— 60 单位同帧实测仍只 2 个副本。
- **提交**：`4fd1cf3`。

### 3.8 **大招音（S3 施放）哑了**——被"音符声浪"饿死

- **现象**：三技能开大**没有大招音效**（加了诞生音之后才出现）。
- **根因**：`MAX_VOICES = 8` 是**整场全局**并发上限，而每次攻击现在有 **3 个音**（挥击+诞生+命中），
  两只她同时开火 ≈ 每秒 8–12 个音 ⇒ 声道常年占满 ⇒ 后到的音（**包括最该响的大招音**）被 `tryAcquire` 直接拒绝。
  真浏览器实测：`tryAcquire 101 次 / 放行 70 / 拒绝 31`，原因分布 `{perUrl:29, voices:2}`。
- **修法**：`SFX_PRI` **优先级**——**发动/部署/阵亡/漏怪 = 事件档**，普攻与命中 = 单位档，**音符诞生等 = 装饰档**；
  满额时**低档让位**（官方 `maxSoundAllowed`/`popOldest` 语义），**被挤掉的音立即停掉**（节点级 `onEvict`）⇒ 并发仍 ≤8、每文件仍 ≤2；**低档不会被静音**，只是不挤高档。
- **提交**：`dc22ec8` + `eb9ea15`。

### 3.9 技能音符的命中音**不分档**（S1/S2/S3 都播普攻那条）

- **现象**：S1/S2/S3 的音符命中，播的都是**普攻的命中音**。
- **根因**：清单里**每个单位只有一个 `hit`**，而 `snap.proj` 的 kind 只有 `note`/`noteSkill`，**分不出是哪一招**。
- **修法**：新增**通用** schema `sfx.units[charId].skillSfx[skillIndex] = { born?, hit?, finish?, loop? }`，
  从官方 bank 解析（`SKILL_SFX_BANKS`）；客户端**按"她当时在开哪个技能"**选文件，**找不到一律回落**单位的 `hit`
  （**没有 `skillSfx` 的干员行为与改前完全一致**）。
- **实测**：S1 `p_imp_mjckyrdglsnt`、S2 `p_imp_mjckyrdnt_r`、S3 `p_imp_mjckyrdslnt` 各自播放；
  清单 diff **只有 `hash` + 她的 `skillSfx`**，其它 **483 个干员零变化**。
- **提交**：`dc22ec8`。

### 3.10 S3 的**持续段循环音**缺失 + 结束方式

- **根因/依据**：官方 `soundFXCtrlBanks` 的 `ON_SKILL_FINISH.skchr_oblvns_3` 是
  `{ targetBank: ON_BUFF_START.oblvns_s_3[loop], ctrlStop: true, ctrlStopFadetime: 0.2 }`
  ⇒ **S3 没有独立的"结束音"文件，停掉循环音就是它的结束**。
- **修法**：新增 `startLoop`/`stopLoop` 原语（真 Web Audio `loop=true`，走音效声道，按单位 key，60 s 兜底，离开战场全部停）。
- **提交**：`dc22ec8`。

### 3.11 技能条满了却**一直普攻、不放技能**

- **现象（所有者实机）**：SP 条读满，她却继续普攻、技能永不发动。
- **根因**：官方「**可充能 2 次，充能至最大层数时自动释放一次**」这条机制**从来没实现**——
  kit 把它留给了引擎的自动触发，而引擎的触发要求「**即将攻击 + 初始范围内有敌人**」；
  她的**持续攻击**会把音符打到范围**外**的敌人、照常回技力 ⇒ **范围空着时充能停在上限**、条满而永不发动
  （实测 `sp=4/4 ch=2/2 activations=0` 一直到采样结束）。
- **修法**：kit 自己以 `reason 'chargeFull'` **立刻**释放一次（PRTS：「…会**立刻**产生额外效果，如立刻释放一次」）：
  **不需要目标、不等攻击、不花**自动操作的 3 s 冷却（那是"操作"的冷却）。挂在 `tick` 钩子 + 成员计时器兜底。
- **提交**：`6524aec`。

### 3.12 一技能释放**不触发 Fever**

- **根因**：§17 的例外是按「**施法瞬间充能是否已满**」判定的，而不是按「**这次释放是不是充能上限造成的**」。
  满充能释放只降到 max−1，回满只要 **4 次落点**；**攻速越过 ≈173**（她天赋 +16、模组 +12，再加一件攻速装就到）
  时**每次释放都在满充能上发生** ⇒ **每一次**都被误判成"充能满自动释放" ⇒ S1 **永不触发 Fever**
  （实测连续 5 次 `chargeFullFlag=true`、`feverLeft=0`；攻速扫描：间隔 1.12/0.78 → 0 次误判、Fever 2 次；**0.60 起 → 17/34 被误判、Fever 只剩 1 次**）。
- **第一次修法**：改为按**事件**判定（`ctx.reason === 'chargeFull'`）。
- **第二次（所有者裁定 2026-10-08）**：**整条例外取消**——原版确实不算，但**本模式是全自动**（**系统代按技能键**），
  所以**充能满那一次也算技能发动，蓄满即触发 Fever**。删除该 `return`，PRTS 原文**保留在文档里**并注明"为什么本模式不适用它"。
- **证据**：反转用例先在旧代码上变红，再改实现；golden 只有 `diy-135` 变（全场 3 次充能满释放，**第 1 次 t≈58.37 s 计量正好 450**；
  快照哈希链**前 5 个完全相同、第 6 个起分岔**，正好落在那个窗口）；`diy-136` 那唯一一次发生在计量 309 → 空操作、逐位不变。
- **提交**：`6524aec`（第一次）+ `3ce6e60`（按裁定取消例外）。

### 3.13 音符锁定敌人后**在外围兜圈**（所有者实机）

- **现象**：音符锁定后不冲上去，而是**绕着敌人转圈**。
- **根因**：「转向速度」被实现成**逐帧权重插值**（`dir = dir·(1−turn) + to·turn`），实际角速度 ≈ `turn × sin θ`，
  在 θ→180° 时趋近 0，并在 `turn·sinθ = trackSpeed·dt / r` 处形成**稳定圆轨道**（S1 实测半径 ≈0.6 格）；
  S1 的官方参数（最短自由移动 0.6 s × 固定 1.7）保证音符**先直飞约 1 格**，所以贴脸敌人在锁定前就被飞过 ⇒ 八只音符全绕回它周围转圈。
  实测：锁定后 27 帧里 **11 帧距离在上升**（0.315 → 0.594，**1.89 倍**），夹角长期钉在 **127°**，0.87 s 后才命中。
- **修法**：锁定后**速度方向 = 指向目标的单位向量**；`转向速度` 只作**每帧朝向变化的上限**（本帧最多转"剩余夹角 × turn"）；
  朝向落在目标**后半球**（点积 ≤ 0）时**直接指向目标**（不能用"指向远离目标"来满足上限）；
  不变式：**锁定后距离每帧严格下降**，不存在轨道半径。锁定同时变**粘**（不回【自由移动】、不换目标；目标死亡按 PRTS 的 `delay` 退场）。
  天赋音符 / S2 钢琴 / S2 风琴 / S3 走同一分支，**一并修好**；各技能的**数值一个没改**。
- **证据**：S1 七个站位从「44/70/70 上升帧」变成**全部 0**；天赋音符同场景 16 帧单调下降、夹角恒 0°。
- **提交**：`ed7058b` + `f5483c0`（注释计数更正）。

### 3.14 攻击挥击音在 0.2.x 的 5 个"技能档"未还原（**调查后决定不做**）

官方 `ON_ABILITY_ON…attack.0/1/2/3/5.1` 与 `combat.*` 全部指向 `p_atk_MJCkyrdnt_h`，而客户端
`normalAttackSfx()` **按文件名**拒绝 `_d/_h/_s` 结尾的音（防"技能命中音被当成普攻音播"）。
**当前清单里它一条都没拒到**（0 条）；若连 plan 的过滤一起去掉，会牵动 **20 名干员 / 25 处**换音（其中 17 处新文件仍会被拒）⇒ **保持现状**。
